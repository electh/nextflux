# 同步与页面更新

体验参照 Reeder 的本地阅读、后台更新与阅读位置保持。Nextflux 继续使用 Miniflux 的逐篇未读和收藏状态；新 Reeder 的时间线位置同步模型不能直接替代 Miniflux 的状态模型。

## 下载

- 已有缓存直接读取 IndexedDB，不等网络。首次启动即使关闭定时同步也会加载文章。
- 订阅源、分类与文章并行请求。首批 30 篇文章写入后页面即可显示；后续每批 200 篇，批次之间让出主线程。
- 首次补齐服务端仍保留的全部已读和未读文章，包含未收藏的已读历史。保存全量遍历任务的 ID 游标，中断后从已提交的批次继续。
- 首次任务结束后，从最初启动时间拉取变化，覆盖中断期间新文章、已读变化与收藏变化。
- 全量历史完成后保存独立覆盖标记；已有旧同步水位但没有覆盖标记的用户会自动补齐已读历史，成功后才切换为增量。
- 后续只请求 `changed_after`。仅请求 read、unread，兼容拒绝 removed 查询的服务端，覆盖新文章和状态更新，避免按发布日期查询漏掉旧日期的新文章。
- 按 `id desc` 和 `before_entry_id` 分页；有可信 total 时判断最后一页，否则继续到空页。不再使用 `limit=0`，也不使用会被新增/状态变化扰动的 offset。
- 完整成功后记录本轮开始时间，向前重叠 2 秒；失败不推进水位。客户端和服务器的时钟需要基本一致。

## 本地缓存

- 订阅源和分类在事务内比对增删改，没有变化就不写入。删除订阅源同时删除其文章和图标。
- 文章只写实际变化的记录；removed 删除本地副本。已读和未读条目都进入缓存；阅读状态不会决定条目是否被同步。
- 数据库 v12 增加 published_at 排序索引，保留原有数据并清理 removed 副本。
- 图标请求按 feed 合并；成功结果缓存 7 天，无图标结果缓存 1 天；离线使用本地结果。

## 页面

- 列表通过 Dexie live query 观察当前来源、过滤器和已加载窗口，不再依赖“同步结束时间”刷新。
- 查询沿排序索引扫描到窗口末尾加一个哨兵条目，无需每次完整排序与统计全部正文。
- 相同记录复用对象，相同结果复用数组。虚拟列表按 article.id 识别行，Header/Footer 类型保持稳定。
- 滚动时保留当前行顺序，并更新已有行状态。新文章显示轻量提示；回到顶部或点击提示后更新顺序。
- 已展开的列表窗口继续保留，不因同步回到第一页。切换来源和过滤器才重置窗口。
- 正文只观察当前文章及其订阅源，其他文章的变化不会重新查询当前正文。HTML 解析按内容缓存，保留阅读模式抓取的全文。
- 侧栏计数扫描复合索引键，不读取正文，也不按每个 feed 分别发起查询。进度提示独立订阅，避免进度导致整个侧栏重绘。

## 调度与兼容性

- 同一页面共享正在执行的同步；支持 Web Locks 的浏览器在同源标签页之间串行执行。
- 页面隐藏或离线时暂停自动请求；恢复可见或在线后按同步间隔检查，失败采用指数退避。
- 登出取消网络请求，并在响应写入和推进水位前检查取消状态。
- Miniflux 2.3.2 起使用 PUT /v1/entries 显式设置收藏，批量标记已读只发一个请求。旧版本拒绝 starred-only 请求时，先读取当前状态再按需调用 bookmark。

## 已知边界

- 目前仍沿用原项目的离线修改语义：离线已读/收藏写入本地，没有持久化上传队列。
- 增量接口只返回服务器仍保留的记录；当前不请求 removed 状态，服务器删除或物理清理历史数据后，已有本地历史副本不自动删除（订阅源删除仍会清理本地副本）。
- 首次后台补齐期间，未读/收藏计数表示已缓存条目，会逐批增加。
- 浏览器不支持 Web Locks 时只保证单页面合并同步。
- 列表查询不为单个订阅源建立每一种过滤/排序的复合索引；稀疏来源可能扫描较多索引项，但不会读取并排序整个文章集合。

## 验证

`npm test`、`npm run lint`、`npm run build`。同步回归测试覆盖首批发布、服务端限流分页、时间边界、旧日期新文章、仅接受 read/unread 的服务端、中断续传、启动期间状态变化、并发合并与取消。独立端口模拟 Miniflux 验证滚动时收到新文章、提示点击更新、正文读取和列表分页；未访问真实账号。
